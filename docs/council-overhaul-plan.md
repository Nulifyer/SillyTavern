# Council-selected Scene details overhaul

The three council members agree on one connected authoring journey. From an
unexpected reply, a reader can understand the current story, inspect available
generation evidence, correct the right native source and explore an alternative
without losing the original conversation.

This plan consolidates the story, control and quality proposals under
docs/evidence/council-overhaul-20261108/. Each member must confirm that it
represents their agreement. Scope approval is separate from final acceptance.
The parent implements. The same members later review source, tests and a fresh
synthetic rendered build.

## Product scope

1. Keep the conversation primary and Scene details optional. Show exact story
   identity and organize details around current setup/memory, selected reply
   context and related stories. Keep a clear close/return action.
2. Show the effective premise and its actual story or reusable-character scope.
   Route correction to the native story override owner. Repair Apply, Cancel,
   Escape, failure and obsolete-owner behavior before promoting the editor.
   Shared character, persona, lore, preset and provider editors keep their owners
   and receive accurate scope descriptions.
3. Show the native effective summary through an owner-provided snapshot. Explain
   its anchor only where known. Distinguish summary, authored instructions, lore
   and retrieval. Disabled, uninitialized, empty, paused and noninjected states
   remain distinct. Route editing/configuration through the one native control
   tree. Opening details never summarizes or claims that a changed field is an
   acknowledged save.
4. Add selected-reply inspection backed by a bounded native client capture.
   Capture allowlisted messages/components and immutable model, provider, preset
   and budgets with full account/story/entity/file/message/swipe/revision
   identity. Keep credentials, authorization headers, sensitive URL query values
   and large media payloads out. Existing filename-only records remain untouched
   and cannot be presented as verified provenance.
5. Label recorded client assembly separately from current setup. If native
   compatibility processing is reconstructed, label it as reconstruction by the
   current converter. Uncaptured provider-adapter and model-template stages stay
   unavailable. No exact additive token accounting from overlapping categories,
   invented inclusion reasons or inference call on inspection.
6. Show bounded parent/branch/checkpoint relationships using native metadata and
   full transcript identity. Use useful origin text and lists rather than a graph
   canvas. Retain native selected-swipe branching and exact-story opens. Explain
   that transcript and chat overrides copy while reusable card/lore/provider
   settings stay shared. Missing legacy references remain visibly unavailable
   and are never guessed from title suffixes.
7. Ensure newly created branches have useful navigation in both directions.
   Native branch and group-save owners must report failure honestly, avoid
   phantom entries, and reject obsolete owner changes. Reads and inspection
   remain available during generation. New mutations obey idle/archive rules.
8. Preserve immediate Start, archive/restore, native message actions, optional
   images/voice/dictation, deep settings, exact model names, explicit overrides,
   one mounted native control tree, classic layout and existing tab recovery.

## Ownership

| Behavior | Owner |
| --- | --- |
| Scene details presentation, section navigation and focus | Workspace presentation using the existing inspector and coordinator |
| Summary selection, injection and correction | Native memory extension |
| Story scenario/example/system overrides and saving | Native script chat metadata owner |
| Immutable captured client context and its storage lifetime | Native itemized-prompt/generation owners |
| Request construction and compatibility conversion | Existing native chat backend and converter |
| Branch creation, snapshots, group saves and transcript activation | Native bookmark, group and chat owners |
| Related-story indexing and archive identity | Existing WorkspaceChats/native recent-chat path |
| Settings mounting/restoration | Existing WorkspaceSettings |

A small read API or shared native operation is acceptable where needed. A second
memory store, prompt assembler, transcript lifecycle or model registry is not.
Do not rely on parent test doubles as the only proof of native contracts.

## Acceptance contract

- Opening details, changing its section and inspecting any available reply do
  not trigger inference, settings writes, summary generation, transcript saves,
  message replacement or composer insertion. Preserve draft text/selection,
  reading position and active-operation ownership.
- Scenario Apply persists only to the intended story. Cancel, Escape and outside
  dismissal do not commit. A different story or a generation starting during an
  open editor rejects obsolete application. A failed save does not claim success
  or leave a false in-memory committed state.
- Summary state comes from the native owner's effective rule, which currently
  skips the final message. An anchor is not proof of an exact covered range or
  recall accuracy. Editing has truthful native persistence/failure feedback.
- Two characters and a cast may share a filename without sharing memory or
  diagnostic ownership. Capture history stays associated with its recorded
  message/alternative/revision after model/preset/budget changes, Continue,
  swipe, rename, delete and reload. Missing or mismatched captures are a useful
  unavailable state, never a fallback to an unrelated cache entry.
- Diagnostic content uses text-safe rendering and allowlisted data. Any
  compatibility reconstruction uses the native converter. Show capture limits
  and unavailable stages rather than silently implying complete provenance.
- Branch tests cover character/cast, selected swipe, nested and legacy stories,
  archives, rename/deleted parents, missing links and failed/obsolete opens.
  Original transcript and selected alternative remain intact. New branch failure
  cannot leave false success or phantom group/history entries.
- Archived stories remain inspectable. New mutation controls cannot silently
  restore a story. Read-only inspection works during a held reply, while edits
  and branch creation respect the existing generation gates.
- Desktop, 320/390/448px phones, 768px intermediate width, enlarged text and
  reduced phone height retain readable identity, wrapping content, reachable
  controls and return paths. New inputs/selects/links enter the focus boundary.
  Native foreground editors and menus own Escape before background Stop.
- Hidden/frozen-tab resume with details open preserves native nodes, draft and
  reading anchor without waiting on connectivity probes, replaying inference,
  opening recovery UI or placing character text in user drafts.
- All existing native provider/prompt/parameter paths remain reachable, explicit
  settings persist, native control IDs remain unique and classic restoration
  returns the same controls to their owners. Late/disabled extensions are honest.

## Verification and delivery

Use local containers with fresh synthetic volumes and neutral fixtures. Parent
owns automated persistence runs. Council members receive separate fixtures and
tabs for final review. No production app/data/config volumes/logs/screens or
shared test85 access. No Juiced runtime/policy/cache changes. Real Juiced tests
are bounded and coordinated through the existing LAN service.

Run relevant unit/lint checks and the full existing browser suite plus new
behavior regressions. Inspect representative desktop and phone renders. Preserve
failed attempts and diagnose them. Passing counts do not replace the council's
own product review. Follow normal immutable multiarch release gates and verify
the actual published image. This request does not authorize another production
redeploy.

Each member supplies a final accept or needs-changes verdict with reasons,
evidence, open findings and satisfaction with the agreed project outcome. Resolve
real objections and have the same members recheck them. Do not invent unanimous
approval or erase remaining limits.

## Exclusions

No mandatory creation or scene wizard, scenario marketplace/catalog, full frozen
world snapshots, branch graph canvas, replacement memory/prompt engine, automatic
recap or summary on opening, generated suggestions, new service-test panels,
export redesign, realtime calling, game-state meters or cast simulation. Existing
native capabilities remain available. These are scope choices agreed by the
council, not deletions from the product.

Physical Pixel lock/GPU restoration, audible quality and paid-provider behavior
remain unqualified without their own evidence. The council's final satisfaction
applies to this accepted scope and observed build, not a guarantee that every
untouched upstream path is defect-free.
