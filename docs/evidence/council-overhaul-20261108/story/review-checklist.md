# Story review checklist

This is a planned walkthrough, not evidence that the implementation passes. Use only the parent-assigned fresh synthetic fixture and a separate browser tab. Coordinate before mutation or persistence checks.

## First-use and return

Open a character profile, read its premise and opening, and Start new story. There must be no title or scene wizard. Send a harmless turn only if the fixture includes a controlled provider and the parent authorizes the operation. Open Scene details and identify character/cast plus exact story. Return to chat and verify draft text, selection and mounted reply nodes. Repeat through profile history and Stories with two filenames that match across distinct characters.

## Correct this story

Read effective premise and source. Open native story overrides, change premise, then Cancel and Escape separately. Neither should save. Apply a new premise, reload and inspect the sibling story and reusable character. They should retain their original premises. Remove the override and verify the shared premise returns. If a shared editor is offered, the action must state its scope before editing.

Inspect summary availability and stored-versus-injected state. Check absent summary and unavailable extension before any correction. With a seeded summary, compare its displayed anchor to native state. Do not infer a covered range. Use the native correction link and confirm the intended story retains the edit after reload. A paused summary can still exist and be injected. No generation should start from inspection.

## Investigate one reply

Select a seeded captured reply. Read exact model and available budgets. Change current setup in a reversible fixture-only way and return to the same capture. Historical values must remain historical. Change swipe or edit the reply; stale context must not be presented as belonging to the changed text. A legacy prompt record should be unavailable or explicitly unverified. Raw detail should be secondary, text-safe and credential-free.

## Explore another direction

Use a selected alternate reply to create a native branch. Confirm the branch ends at that selected reply, the original story remains unchanged, and source/branch navigation works both ways. Read the branch copy explanation. Open a nested branch, an archived relation and a missing parent. A missing/failed target must keep the active transcript and draft. Archive must never restore implicitly. Legacy rename may show unavailable origin if explicitly explained.

## In-flight and phone return

During a held reply, open read-only details. Expand a section, focus a control and allow stream updates. Keep expansion and focus stable. Mutations must obey the generation gate. Close nested UI with Escape before testing background Stop.

At 320, 390 and 448 pixels with enlarged text and reduced height, inspect memory, premise and branches, open the native editor, and return to the same draft. Long names must preserve enough identity to distinguish stories. Confirm reachable close action, interior scrolling and keyboard focus. Use parent automated evidence for true hidden/frozen resume unless an isolated run is explicitly coordinated; do not confuse screenshots with suspension or keyboard evidence.
