# Story scope vote

Approve the connected Scene details scope, subject to the concrete criteria below. This is approval of the delivery plan, not acceptance of an implementation.

The control and quality members support the same optional story workflow. Their concerns materially improve the proposal. Historical context needs stronger identity than the old prompt cache. Archived stories and generation need explicit mutation gates. The normal chat remains the primary task.

## Agreed delivery

- Keep character profile, exact-story selection and immediate Start new story. Add user-invoked Scene details sections for story setup and memory, reply context, and related branches.
- Show the effective premise and whether its source is this story or the reusable character. Open the native story override editor with real Apply and Cancel behavior, captured owner identity and truthful shared-versus-story copy. A cast-wide override must explain that it applies to its members in this story.
- Show effective summary state through the native summary owner. Explain that the stored anchor is not proof of complete source coverage. Keep generated summary, authored note, attached lore and retrieval distinct. Provide correction links to existing controls without generating on inspection.
- Record a bounded native client stage with full story owner, file, message, swipe and response identity. Clearly distinguish current setup, recorded client assembly, any reconstruction, and unavailable backend/model-template stages. Legacy filename-only prompt records must not masquerade as verified historical context. Exact provider-rendered prompts are not required when the native owners cannot observe them.
- Expose parent and related branches using native metadata and exact transcript opens. Retain selected-swipe branching and the original story. Explain that transcript and chat overrides copy while shared character, world and provider settings remain shared. Use useful lists and origin text; a graph is unnecessary.

## Binding review criteria

1. Two characters and a cast with identical story filenames remain isolated in memory, history and diagnostics. Changing a model, premise, swipe or message cannot relabel an old capture as current historical evidence.
2. Apply a story premise, reload, open a sibling story and inspect the card. Only the intended story changes. Cancel, Escape, outside dismissal, changed owner and failed save must not produce a false saved result or apply the pending edit to another story.
3. Native summary state handles unavailable extension, absent summary, paused updates and noninjected summary distinctly. Correcting it preserves the native owner and actual persistence rules. No summary accuracy or full-range claim is invented.
4. Inspection preserves mounted message nodes, draft text and selection, story identity and inference count. It remains usable during generation. Mutating scene editors and branches require existing idle and archive rules. Archived links never silently restore a story.
5. Character and cast branch tests cover a selected swipe, nested branches, legacy records, archived targets, a renamed or deleted parent and a failed open. Missing or ambiguous ancestry is visible and never resolved by a title-suffix guess. Honest unavailable ancestry after legacy rename is acceptable; new branches need useful navigation in both directions.
6. At 320, 390 and 448 CSS pixels, enlarged text and reduced height, the story identity, section controls, editors and return path remain usable. Keyboard nested Escape closes the foreground menu/editor before background Stop. Returning after a hidden/frozen tab preserves the native reading anchor and reply nodes.
7. Native advanced controls, exact model identifiers, manual settings and classic layout remain available. There is no mandatory naming/setup step, recovered-reply panel, automatic inference replay or insertion of character text into user drafts.

## Excluded and unresolved

Exclude a creation wizard, scenario catalog, full-state checkpoints, replacement memory or prompt engine, model registry/proxy, automatic recap generation, graph canvas, export overhaul and new live-service policy. Production and shared test85 remain prohibited.

No scope objection remains after peer discussion. Runtime behavior, rendered UI and persistence are still unverified. Final acceptance requires the same council's review of source, parent test evidence and an assigned fresh synthetic fixture. A parent test count alone will not establish the story outcomes above.
