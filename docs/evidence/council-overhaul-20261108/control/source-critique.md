## Findings sent

- Optional diagnostics can currently stop generation. `itemized-captures.js:beginClientCapture` calls `crypto.randomUUID` without a failure boundary. `finishClientCapture` hashes before entering its storage `try`. An absent secure-context API or rejected digest can therefore reject native generation or saving. Existing `utils.js:uuidv4` already handles the missing UUID API. Make capture creation, request projection and finalization best effort. An unavailable capture is acceptable. A failed chat turn caused by diagnostics is not.
- Capture truncation needs explicit disclosure. `safeMessages` silently clips string prompts and keeps only the last 300 messages. Components clip independently at 32,000 characters. The overall size guard only reports a later whole-record omission. A reader cannot treat these silent partial strings as complete captured text. Mark each relevant omission and its limits.
- The captured budget is incomplete. `script.js` initializes `this_max_context` with `getMaxPromptTokens`, which is usable input capacity after output reservation. `workspace-scene.js` accurately calls this available prompt budget, but configured total capacity is absent, and output reservation appears only inside raw parameters. Capture and display the native configured total and output reservation independently. Distinguish recorded request values if extension hooks changed them.
- Summary editor scope copy is inaccurate. The combined editor/configuration link says edits affect this story, although `extension_settings.memory` owns shared automation, source, prompt, template, position and depth. Distinguish story summary text from shared configuration. Author's Note also has multiple native scopes.
- Related-story integrity can be ambiguous. `workspace-scene.js:related` chooses the first peer with a matching integrity value. Native JSONL import preserves the header and its integrity in `src/endpoints/chats.js`, so a copied import can create more than one candidate under the same character. Use recorded parent file plus integrity where applicable, otherwise require a unique match or report ambiguity.
- Capture rename completion lacks a reliable refresh boundary. `script.js` listeners discard the promise from `renameClientCaptures`. Reload renders the new owner before this alias write, and the details signature does not include capture-store readiness. The later 500 ms chat refresh is timing, not acknowledgement. Await the native rename listener or emit an identity-guarded capture-ready event so slow storage cannot leave a stale unavailable view.

## Strengths to preserve

The new capture owner allowlists request parameters and extracts only text message parts. Headers, proxy passwords, arbitrary body configuration, media bodies and tool payloads are excluded. Owner bindings include account, character or cast, filename and native integrity. Reads verify message index, selected swipe and response hash. Legacy filename-only itemization is not consulted. These are source observations, not yet exercised privacy or isolation results.

The details view labels the captured client stage and unavailable server conversion, final provider and model template separately. It provides a readable unavailable state and optional technical disclosures. Scenario editing now uses a native confirmation popup and checks original owner and generation state. The conditional save path now returns a boolean and supports an expected owner. These changes align with the agreed ownership rules, pending failure and rendered checks.
