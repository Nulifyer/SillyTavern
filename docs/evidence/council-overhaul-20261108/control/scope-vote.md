# Control scope vote

Approve the connected Scene details delivery plan with the conditions below. This approves scope, not implementation. I read the story and quality proposals and discussed concrete risks with both members and the parent. No scope objection remains.

## Agreed outcome

A reader can inspect the current story's setup and native memory, open the right correction editor, inspect a selected reply's recorded context, and follow native related stories. Scene details remains optional. Chat, immediate Start and exact transcript selection remain the ordinary path.

The parent implements through native owners. Workspace presents state and navigation. Native summary, scenario, bookmark, transcript, settings and generation modules retain their rules, writes and operation lifetimes. A small native read facade or guarded edit operation is appropriate. Another memory store, prompt pipeline, model registry or transcript controller is not.

## Conditions retained from discussion

1. Record bounded, allowlisted client diagnostics at the native generation owner. Associate them with the full character or cast identity, exact file, message, selected swipe and response revision. Snapshot exact model identifier, provider, preset, configured context and output reservation. An immutable historical view must not read today's settings as yesterday's configuration.
2. Distinguish current setup, captured client stage, any native compatibility reconstruction and unavailable provider/model-template stages. A captured client request is a useful minimum. No new server prompt archive or comprehensive provider wire capture is required. Do not fabricate lore exclusion reasons or exact source coverage.
3. Treat legacy filename-only itemization as unverified or unavailable. Never borrow another owner's same-filename record, or relabel a changed swipe or edited response as the captured original. Preserve existing legacy records without eager migration or deletion.
4. Expose native story overrides with real Apply and Cancel behavior. Escape and dismissal must not apply pending text. Capture the original owner and file, reject obsolete saves, preserve sibling stories and shared cards, and report failed persistence honestly.
5. Read effective summary state from its native owner. Distinguish absent, paused, unavailable and noninjected state where the owner can establish it. A stored message anchor does not establish a complete covered range. Correction links state their actual story/shared scope.
6. Inspect archived stories without implicit restoration. Mutation follows existing idle and archive gates. Read-only inspection works during a held reply and preserves native Stop. New interactive controls enter the mobile focus boundary. Refresh preserves focused inputs, open disclosures, transcript nodes and draft selection.
7. Use exact native opens for branch and checkpoint relationships. Preserve the source transcript and selected swipe. Newly created branches have useful navigation in both directions. Missing or ambiguous legacy ancestry may remain unavailable; title-suffix guesses are forbidden. Failed or obsolete opens preserve the current story.
8. Preserve one mounted native settings tree, advanced controls, All controls, classic restoration, custom parameters, prompts, provider forms and explicit context/sampling values. Discovery remains optional metadata. No model policy, runtime or cache changes.
9. Render untrusted context as text. Capture diagnostic fields by allowlist, excluding credentials, authorization/header configuration, sensitive endpoint query values and media bodies. Do not persist a complete raw request object merely to fill an inspector.

## Required evidence

The final review needs finished source identity, meaningful checks and an assigned fresh synthetic fixture. It must cover same-filename character/cast isolation, swipe/edit/Continue changes, model and budget changes, rename/reload, legacy absence, stale work, scenario Apply/Cancel/failure, summary correction, branch navigation/failure and archive behavior. Desktop and 320/390/448px interaction checks must show accessible return paths and native control preservation. Existing tab recovery, media opt-in and classic restoration remain regression requirements.

Exact criteria and observed source risks are in `scope.md`. Peer evidence is in `../story/scope.md`, `../story/scope-vote.md` and `../quality/scope.md`. The native itemized cache currently keys by `chatId`; records replace by `mesId`; OpenAI budget itemization reads live settings. These observations support the stronger provenance requirement. They do not prove the forthcoming implementation is defective.

## Exclusions and review status

Exclude creation and export redesign, service-test panels, mandatory setup, generated suggestions, full-state snapshots, automatic summaries, a branch graph, continuous voice, cast simulation and production/shared test85 access. Existing native capabilities remain available.

The scope is coherent and feasible through existing owners. Runtime behavior, rendered states and persistence are unverified. I remain in this council assignment for implementation consultation and final acceptance. A test count alone will not satisfy the criteria above.
